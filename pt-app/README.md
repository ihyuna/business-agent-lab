# PT 기록 앱 MVP (웹 프로토타입 v3)

PT 트레이너가 회원 수업을 준비하고, 진행하고, 마무리하는 흐름을 눌러 볼 수 있는 웹 프로토타입입니다. 실제 앱은 iPad 앱으로 만들 예정이고, 이 프로토타입은 화면 흐름을 확인하기 위한 것입니다. 화면 크기는 iPad 9세대 가로(1080×810)에 맞췄고, 디자인은 아직 다듬지 않았습니다.

**데이터는 트레이너 수첩의 실제 기록입니다.** 기록 사용은 회원님들께 허락을 받았고, 이름은 성+00 코드(이00_1, 이00_2, 이00_3, 김00, 정00, 최00)로 바꿨습니다. 실명은 넣지 않습니다. 수첩에 없는 값(역할, 여유 횟수, 쉬는 시간, 기구 눈금 등)은 '예시'나 논문 기준 임시값으로 표시했습니다.

## 여는 법

크롬 등 브라우저에서 `app.html`을 열면 웹앱(`web/index.html`)으로 넘어갑니다. 시연판은 `demo.html`을 열면 됩니다(파일로 열거나 웹 주소로). 서버나 설치가 필요 없습니다. `index.html`은 Claude 아티팩트용 조각입니다. 입력한 내용은 그 브라우저의 localStorage(`pt-mvp-proto-v3.3`)에만 남고, 화면의 '처음 상태로 되돌리기'로 지울 수 있습니다.

오른쪽 '시나리오 따라 하기' 패널이 8개 장면을 안내합니다. 각 단계에서 직접 누르거나 '대신 하기'를 누르면 됩니다.

## 화면

1. **오늘**: 오늘 수업 목록, 오늘 메모
2. **수업 준비**: 지난 기록 요약과 오늘 계획(무게·횟수 자동 채우기)을 한 화면에
3. **수업**: 시작할 때 컨디션 확인, 세트마다 한 번 누르기, 남은 시간 띠
4. **마무리**: 오늘 바뀐 것, 다음 같은 분할 수업의 초안

숫자 색:

- **주황**: 컨디션(수면·피로·근육통이 '나쁨') 때문에 바뀐 숫자입니다. 기본 숫자는 컨디션이 모두 '보통'일 때를 기준으로 합니다.
- **보라**: 수업 중 세트 결과가 계획과 많이 달라서 남은 세트를 다시 맞춘 숫자입니다.
- 색이 칠해진 숫자를 누르면 원래 숫자, 바꾼 근거, '원래 숫자로' 버튼이 나옵니다.

역할별 기준, 여유 횟수(RIR), 쉬는 시간, 기구 눈금 같은 값은 트레이너 답을 받기 전까지 쓰는 논문 기준 임시값이거나 예시입니다.

## 구조

| 파일 | 내용 |
|---|---|
| `src/00-head.html` | 스타일과 페이지 틀 |
| `src/10-data.js` | 상수, 역할별 기준, 종목 사전, 수첩 기록(코드 이름) |
| `src/20-logic.js` | 숫자 채우기, 컨디션 반영, 실시간 다시 맞추기, 시간 계산 |
| `src/30-views.js`, `src/31-views2.js` | 화면 |
| `src/35-guide.js` | '시나리오 따라 하기' 장면 |
| `src/40-actions.js` | 버튼 동작 |
| `build.sh` | `src/`를 합쳐 `index.html`, 시연판 `demo.html`, 웹앱 `web/index.html`, 웹앱 입구 `app.html`을 만듭니다 |

`index.html`은 빌드 결과물입니다. `src/`를 고친 뒤 다시 만들어 주세요.

## 빌드와 테스트

```sh
sh build.sh          # index.html, demo.html, web/index.html, app.html 다시 만들기
node test/smoke.js   # 8개 장면을 끝까지 자동으로 돌려 보고 결과와 오류를 출력
node test/check.js   # 장면 1~7을 한 단계씩 돌리며 시간 띠·색 표시 상태를 출력
```

테스트는 Playwright와 Chromium이 필요합니다. `check.js`는 `smoke.js`가 만든 `test/page.html`을 쓰므로 `smoke.js`를 먼저 돌립니다.

# 짐노트 웹앱 (`web/`)

시연판(`demo.html`)과 같은 화면·계산을 쓰되, 트레이너가 실제로 쓰도록 바꾼 웹앱입니다. 지도교수님 피드백(11/11)대로 아이패드 앱 대신 웹앱이고, 화면 기준은 그대로 아이패드 9세대(1080×810)입니다.

흐름: **소개(랜딩) → 로그인/계정 만들기 → 처음 설정(이름 → 홈 화면 추가 안내) → 앱(빈 노트)**. 앱의 각 화면은 처음 열 때 한 번, 어두운 배경 위에 설명하는 곳만 밝히고 카드로 하나씩 안내합니다(D77, 워크플로우 5-11). 설정 → '화면 안내 다시 보기'로 다시 봅니다.

## 계정과 저장

트레이너마다 자기 계정으로 들어가고, 자기 기록만 봅니다.

- **클라우드 계정 (Supabase)**: `web/config.js` 에 Supabase Project URL과 anon 키를 넣으면 켜집니다. 이메일·비밀번호로 가입하고 어느 기기에서든 로그인합니다. 기록은 `notebooks` 표에 계정당 한 줄(앱 상태 전체 JSON)로 저장되고, 행 단위 보안으로 본인 줄만 읽고 씁니다(`web/supabase.sql`). 기기에도 사본을 두어 인터넷이 끊겨도 쓰고, 연결되면 다시 올립니다.
- **이 기기 계정**: `config.js` 가 비어 있으면 서버 없이 이 브라우저 안에서만 계정을 나눕니다(비밀번호는 해시로만 저장). 다른 기기에서는 같은 계정으로 들어갈 수 없습니다.

Supabase 준비: 프로젝트 만들기 → SQL Editor에서 `web/supabase.sql` 실행 → Authentication → URL Configuration의 Site URL을 앱 주소로 → Project URL과 anon 키를 `config.js` 에. service_role 키는 넣지 않습니다.

## 시연판과 다른 점

- 오늘 날짜와 수업 중 시계가 실제 시각입니다(쉬는 시간 = 앞 세트를 끝낸 뒤 지난 시간).
- 시나리오 안내, 위쪽 도구 줄, 예시 취소·안 옴이 없습니다.
- 새 계정은 빈 노트로 시작합니다. 기록을 옮길 때는 설정 → 백업 파일 불러오기.
- 설정: 내 계정(이름·센터, 로그아웃, 화면 안내 다시 보기), 백업 내려받기·불러오기, 내 기록 모두 지우기. 트레이너 이름은 경과기록지와 회원 안내서의 서명 줄에 들어갑니다.
- 서비스 워커(`sw.js`)와 `manifest.webmanifest`: 한 번 연 뒤에는 인터넷 없이 열리고, 아이패드 사파리에서 '홈 화면에 추가'하면 앱처럼 열립니다.

여는 법: GitHub Pages를 켜면 `https://ihyuna.github.io/business-agent-lab/pt-app/web/` (저장소 Settings → Pages → Branch `main`, 폴더 `/ (root)`).

코드: `src/` 를 시연판과 같이 쓰고, 웹앱에만 `src/50-web.js`(계정·소개·처음 설정·저장)와 `src/web.css` 가 더 들어갑니다(`35-guide.js` 는 빠짐). 소스 안의 `WEBAPP` 값으로 둘을 가릅니다. 설정은 왼쪽 목록 + 오른쪽 내용(아이패드 설정 앱처럼, `src/settings.css`)이고, 두 디자인 모두 다크 모드(라이트·다크·자동)가 있습니다(기록부 다크는 `src/dark.css`). 기록부는 애플 디자인의 여백·모서리 단위, 버튼 크기, 누름 반응, 창 움직임을 같이 씁니다(`src/chart.css`). 설정 아이콘은 한 가지 색 선 아이콘입니다. 화면 디자인은 '기록부'(`#device.chart`, `00-head.html`)와 '애플 디자인'(`#device.apple`, `src/apple.css`, 시연판·웹앱 공통) 두 가지이고 설정에서 바꿉니다. 애플 디자인은 emilkowalski/skills 의 apple-design 스킬(MIT) 원칙을 따랐습니다. `web/sw.js`, `web/manifest.webmanifest`, `web/config.js`, `web/supabase.sql`, 아이콘은 직접 고치는 파일입니다.

```sh
sh build.sh          # index.html, demo.html, web/index.html, app.html(웹앱 입구)
node test/web.js     # 이 기기 계정 + 가짜 Supabase로 가입·처음 설정·수업·새로고침·로그아웃·계정 분리·다른 기기 로그인 확인
```
