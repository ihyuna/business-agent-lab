## 1. 한 줄 요약

두 자료는 **같은 앱의 두 층**을 설명한다.

| 층 | 출처 | 내용 |
|---|---|---|
| 기록·관리 층 (앱의 몸통) | 앱 설명 | 회원 목록, 한눈에, 수업 기록, 수업 상세, 예정 루틴, 주의사항/확인사항, AI 기록 검색 |

앱 설명이 꼽은 핵심 가치는 **"기록을 얼마나 많이 남기는가"가 아니라 "그 기록을 다음 수업에서 얼마나 유용하게 활용하는가"** 이다 [앱 설명 3]. [해석] PDF는 이 '활용'을 추천 엔진으로 구체화한다.

PDF의 공식 주제: *"회원별 운동 수행 데이터와 훈련 맥락을 활용한 AI 기반 퍼스널트레이너 의사결정 지원 앱 개발"* [PDF 표지]. PDF 1.2는 '모바일 앱'으로 정의한다. → 인터뷰: 기기는 iPad 앱으로 결정 (D02, 15절 1번).
핵심 문장: **"트레이너가 ‘무엇을 왜 할지’를 정하면, AI가 ‘이 회원에게 오늘 어느 정도로 할지’를 회원별 데이터로 보조한다."** [PDF 1.2]

앱 설명만 보면 "기록 관리 앱"이지만, PDF는 연구 성과물의 중심이 **추천 엔진**임을 분명히 한다. 기록 층은 추천 엔진이 쓸 데이터를 모으는 기반이므로 둘 다 MVP 목표다 (D04).

## 3. 방향 전환 (PDF 1.1)

- 초기 기획: PT 수업 **녹음 → STT → 생성형 AI로 기록 자동화**. **폐기됨.**
- 이유: 트레이너 평가상 AI 기록이 부정확하면 다시 전부 검토해야 해서 오히려 업무가 늘어남.
- 전환 후: "‘AI가 기록을 대신 작성하는 시스템’에서 ‘기록을 활용하여 트레이너의 판단을 보조하는 시스템’으로 전환하였다."
- 시사점: 기록은 트레이너가 **빠르게 직접** 입력하는 UX가 중요하다.
- → 인터뷰: 이현아님이 녹음·STT를 완전히 빼기로 결정 (D01). 설문에서도 음성 자동 기록에 "아니요"[설문 Q15], 이유는 "말보다 글이 더 정보 전달력이 좋아서."[설문 Q15-1]라고 답했다.

| 장기 훈련 방향 | 주도 | 참고정보 |
| 당일 훈련 목표 | 주도 | 해석 |

| 현재 수행 가능 수준 | 경험 판단 | 데이터 기반 보조 |

## 5. 트레이너 현장 요구 5가지 (PDF 2장)

1. 직전 중량 불러오기가 아니라 **전체 기록 기반 개인 수행 특성** (이 회원의 부하-반복수 관계)
2. 운동 **순서**가 아니라 선행 운동이 워밍업/메인이었는지, 세트 수, **RIR**이 중요
3. 운동마다 **역할**이 다름: 워밍업, 메인, 보조, 마무리. PDF 원문은 예시 4종("워밍업, 메인 운동, 보조운동, 마무리 운동 등")이고, 인터뷰 후 6종이 됐다 (D39, 목록은 [data-model.md 부록](../design/data-model/data-model.md#부록-선택지-목록)).
4. 당일뿐 아니라 **최근/주간 훈련량과 progression 방향**. 단, "감량 시 볼륨 유지, 증량 시 볼륨 증가" 같은 현장 규칙을 그대로 구현하지 않고 체성분 목표와 운동 적응 목표를 분리. → 인터뷰: 이 규칙은 AI 규칙이 아니라 트레이너가 고르는 훈련 방향 + 진행 방식으로 저장한다 (D19).
5. **Expected Performance 및 수행 편차 탐지**: 평소보다 크게 낮거나 높으면 알려줌. 원인 진단은 제외 (D16).

## 6. 문헌 기반 설계 원칙 (PDF 3~17장)

구현에 직접 영향을 주는 규칙만 추렸다. 이 원칙들은 인터뷰보다 우선한다([README 파일 지도](../README.md#파일-지도)). 결정 번호로는 D11·D13~D15.

| 원칙 | 근거 | 구현 의미 |
|---|---|---|
| 논문 수치를 증감 계수로 하드코딩하지 않음 | 3·16장 | "RIR 1 → 다음 중량 -10%"(16장의 금지 예시) 같은 규칙 금지 |
| 단일 지표(임의 피로공식)를 만들지 않음 | Scott 2016, 16·17장 | volume, effort, 목적, 휴식, 운동 종류를 **원자료로 따로 저장** |
| RPE는 유효하지만 생리값 아님 | Lea 2022 | RPE 저장, 절대값 취급 X |
| RIR은 평균 ~0.95회 과소추정, 기준값 아님 | Halperin 2022 | RIR 저장, 불확실성 고려 |
| 운동 순서 ≠ 피로 척도 | Nunes 2021 | "몇 번째"가 아니라 선행 운동의 실제 수행량·effort 사용 |
| 일반 %1RM-반복수 관계는 초기 baseline | Nuzzo 2024 | 데이터 없는 회원은 일반 기준으로 시작, 운동별로 다를 수 있음 |
| 직접 측정 1RM은 신뢰도 높음 (test-retest ICC 중앙값 0.97) | Grgic 2020 | 1RM 테스트 값 입력 가능하게 (O20) |
| 개인화가 더 나을 수 있음 | Jukic 2024 | 회원별 보정 |
| 개인화가 항상 낫지는 않음 | Greig 2023 | **개인화 효과 자체를 검증 대상**으로 (baseline과 비교) |
| 고볼륨·failure 근접 시 피로 증가 | Varela-Olalla 2025, Vieira 2022 | 선행 세트의 RIR/volume을 맥락 변수로 |
| Autoregulation이 최대근력에 유리 | Huang 2025 | 동적 조정 접근의 근거일 뿐, "‘AI 추천이 증명되었다’는 근거로 사용하지 않고" |
| 목표(근력/근비대/파워)마다 중요한 변수 다름 | Currier 2026 ACSM | 추천은 Trainer Intent에서 출발 |
| 고부하 ≠ 모든 목표의 정답 | Refalo 2021 | "‘더 무거운 중량’ 자체를 모든 목표에서 progression의 정답으로 취급하지 않는다." |
| 중량↑, 반복수↑ 둘 다 유효한 progression | Plotkin 2022 | 추천 방향 **Increase / Maintain / Adjust**(15장) + 어떤 변수("Load, Repetitions, Sets, Effort Target, Rest", 8.3) |
| 볼륨은 수확체감 | Pelland 2026 | 이번 주 볼륨에 1.1을 곱해 다음 주 목표로 삼는 식의 일률 규칙 금지(8.4) |
| 피로도 72% 같은 점수 금지 | 17장 | 추정 대상은 "피로"가 아니라 **다음 수행 가능 범위** |
| 결과는 한 값이 아니라 **범위** | 12.1 | 예: "예상 반복수: 8~11회" |

PDF 5.3·5.4·6.1의 인용 상자 라벨이 본문과 맞지 않는 문제는 15절에 적었다. 위 표의 저자 표기는 본문 기준이다.

## 7. 시스템 개념 (PDF 9·12·13·28장)

```
Trainer Intent → Scientific Baseline → Member Performance Model → Current Context
→ Expected Performance → Recommendation → Trainer Decision → Actual Performance → Model Calibration
```

두 단계를 반드시 분리한다 (D14). 12장: "즉 본 연구에서는 ‘할 수 있는 것’과 ‘해야 하는 것’을 구분한다."
- **Expected Performance** = f(회원별 수행특성, 운동, 현재 세션 맥락, 최근 훈련기록) → 예: 이 중량이면 예상 반복수 8~11회
- **Recommendation** = g(Expected Performance, Trainer Intent, Training Goal, Progression State) → 워밍업이면 최대치 근처를 시키지 않음
- → 설계: 예상 수행의 출발점은 일반 운동과학 기준이다(10장 "기존 운동과학에서 확인된 일반적인 기준을 출발점으로", 11.1 "초기 기준점(Baseline)"). 추천 단계에서 역할별 범위는 논문 수치가 아니라 트레이너 본인의 기준(설정값)에서 출발한다 (D18). 역할에 따라 무게·세트·횟수·쉬는 시간이 달라진다는 것은 인터뷰에서 나왔다 [인터뷰 기능].

회원별 수행모델 4단계 (11장): 일반 기준 → 운동별 기준 → 회원별 수행특성 → 현재 상황 보정.

목표 계층 (14장): 회원 장기 목표 → 훈련기간(블록) 방향 → 오늘 세션 목표 → 개별 운동의 목적·역할. → 인터뷰: 훈련 방향(블록)을 쓴다고 답했다. 방향 = 발전/유지/조절/집중 (R02, D29). 몇 주 단위인지는 답이 없다 (O29). 각 층의 이름은 [glossary.md 2절](../glossary.md#2-목표와-방향-층이-다르니-섞지-않는다).

## 8. 데이터 설계 원칙 (PDF 18~23장)

- **계층: 회원 → PT 세션 → 운동 → 세트** (D23). 세트 단위 기록이 필수다. 앱 설명 예시의 수업 요약(세트 18/18, RPE 7, [앱 설명 4-3])만으로는 부족하다.
- **고정정보와 변하는 정보 분리.** 목표·체중·훈련방향은 이력으로 보존하고 덮어쓰지 않는다 (D24). 과거 기록은 당시의 목표·맥락과 함께 재구성 가능해야 한다.
- **정형 + 자유메모.** 운동명, 중량, repetitions, sets, RIR/RPE, 운동 목적은 "가능한 한 일정한 양식으로 저장한다." 나머지는 메모.
  - 회원 수준: **장기메모**(장기간 계속 참고), **단기메모**(가까운 다음 수업에서 다시 확인). [해석] 앱 설명의 주의사항·확인사항과 대응시켜 한 테이블에 종류로 구분했다 (D40).
  - 세션 수준: **Session Memo**
- **회원 데이터 (19장):** 식별정보(최소), 장기 훈련 목표(이력), **체성분 단계**(감량/유지/증량, 훈련목표와 별개. 예: "감량 중 + 근력 유지"), 실제 운동기록, 장기/단기 메모.
- **보류 (20장):** 나이, 성별, 키, 체중, 운동경력은 AI 필수 입력 아님. 신규 회원 Cold Start에 쓸지 인터뷰 후 결정. → 인터뷰: Cold Start = 키·체중·근육량(트레이너 표현 "근육양") + 몸 쓰는 감각 5항목으로 정했다 (R03, D30). 성별·나이는 선택 입력 (D31).
- **세션 데이터 (21장):** Trainer Intent(오늘 목표·방향), Pre-session Context(당일 컨디션), Actual Session Record(실제 운동·세트). 계획과 실제의 차이도 답할 수 있어야 함.
- **Pre-session Context는 최소화 (22장).** 선택 기준은 트레이너가 실제로 확인하는 것, 그리고 그 정보로 세팅이 실제로 얼마나 바뀌는지다. 통증·새 불편감은 단순한 예측 변수보다 **트레이너가 반드시 확인해야 할 주의정보**로 활용하는 방향을 검토한다. → 인터뷰: 수면·피로·근육통·통증을 다 물어본다 (R05, D33). 그 정보로 세팅을 얼마나 바꾸는지는 아직 답이 없다 (O08).
- **제외 (23장):** 센서 데이터(velocity, HRV), 영양·수분·카페인·일상활동. 장비 없이 동작해야 함 (D10). PT 외 개인운동은 향후 가치 있음, 기록 없음 = "알 수 없음"(운동 안 함 아님). → 인터뷰: 식단·생활·개인 운동은 브리핑 메모로는 저장하되, 예측·추천 입력에는 쓰지 않는다 (D42).

## 9. 피드백 루프와 편차 탐지 (PDF 24·25장)

세 가지를 **따로** 저장한다:
1. **AI Recommendation**: AI가 제시한 세팅
2. **Trainer Decision**: 트레이너가 최종 선택한 세팅 (채택/수정/거부)
3. **Actual Performance**: 회원의 실제 수행

이 세 값이 있어야 예측오차, 트레이너 수정 정도, 수정이 결과와 어떻게 연결됐는지 연구할 수 있다.
앱 설명의 예정 루틴은 **계획**(plan_)이고, 세트 직전에 트레이너가 최종으로 정한 값(Trainer Decision, dec_)과 따로 저장한다. 그래서 세트 한 줄에 계획·결정·실제를 함께 두고, AI의 예상 수행(expectation)과 추천(recommendation)은 별도 테이블에 둔다 (D25, D14). 자세한 규칙은 [data-model.md 3-5](../design/data-model/data-model.md#3-5-종목과-세트).

편차 탐지: 예상 8~11회인데 실제 5회면 "개인 예상범위에서 벗어난 수행으로 표시할 수 있다". 원인은 진단하지 않고 데이터상 차이만 보여준다 (예: 선행 workload가 과거 유사 세션보다 높음, 이전 세트 effort가 높았음, 최근 동일 운동보다 감소). 원인은 트레이너가 태그로 남긴다 (D16, `deviation_review`, 쿼리 Q10).

## 10. 연구질문 (PDF 26장)

PDF 원문 그대로:
- **RQ1. 훈련 맥락정보의 가치:** "회원의 과거 운동 수행기록에 훈련 목적, 운동 역할, 노력도(RIR/RPE), 세션 내 선행 수행정보를 추가로 반영하는 것이 단순 과거 수행기록만 사용하는 방식보다 이후 운동 수행을 더 잘 설명하거나 예측하는가?"
- **RQ2. 회원별 개인화의 가치:** "일반적인 운동 수행 기준에 회원별 과거 수행 데이터를 이용한 개인화 보정을 추가하는 것이 일반 기준 또는 최근 수행기록만 사용하는 방식보다 해당 회원의 이후 운동 수행을 더 정확하게 예측하는가?"
- **RQ3. 실제 트레이너 의사결정에서의 가치:** "회원별 수행모델과 현재 훈련 맥락을 바탕으로 제시된 중량·횟수·세트 권장 범위 및 근거가 퍼스널트레이너의 운동 세팅 의사결정에 유용한가?"

MVP 함의: 앱은 **여러 예측 방식을 같은 세트에 함께 계산·기록**해야 같은 데이터로 RQ1·RQ2를 비교할 수 있다 (D17). 화면에는 하나만 보여 준다. 이 문서가 연구질문과 예측 방식의 대응 기준이다. 각 방식이 무엇을 계산하는지의 정확한 정의는 [data-model.md 3-6](../design/data-model/data-model.md#3-6-ai-관련).

| 예측 방식 | 한 줄 뜻 | 연구질문에서의 역할 |
|---|---|---|
| population | 일반 공식만. 회원별로 학습한 보정 없음 | RQ2 비교 기준 |
| recent | 같은 종목 직전 기록 그대로 | RQ2 비교 기준 |
| personal | 일반 공식 + 회원별 보정 (맥락 없음) | RQ2 검증 대상, RQ1 비교 기준 |
| personal_context | personal + 오늘 맥락(목적·역할·노력도·선행 수행) | RQ1 검증 대상 |

'검증 대상'은 나아지는지 보려는 방식, '비교 기준'은 그 방식과 견주는 방식이다. [해석] RQ1의 "단순 과거 수행기록만 사용하는 방식"은 personal로, RQ2의 "일반 기준"과 "최근 수행기록만 사용하는 방식"은 population과 recent로 대응시켰다. 비교 쿼리는 Q8-c.

RQ3는 추천마다 채택·수정·거부, 수정 폭, 이유 태그를 기록하고(Q8-a, Q8-b), 유용성 평가는 사용 후 인터뷰·설문으로 한다. 추천마다 유용성 점수를 받지는 않는다(입력 부담).

## 13. MVP로 가는 계획

로드맵은 [README 다음 단계](../README.md#다음-단계) 하나만 둔다 (D48). 이 문서에서 나온 순서의 근거만 남긴다.
- 기록 앱을 먼저 내서 트레이너가 실제 데이터를 쌓기 시작해야 한다. 개인 보정은 "회원의 기록이 축적되면"[PDF 11.3] 가능하므로, 개인화(RQ2)는 같은 종목의 반복 기록이 쌓여야 검증된다 (D50).
- 추천 엔진 v1은 일반 공식(population) + 트레이너 역할별 기준부터 만들고, 개인화·맥락 보정은 그다음이다 (D49). 논문 수치를 계수로 넣지 않는다 (D13).
